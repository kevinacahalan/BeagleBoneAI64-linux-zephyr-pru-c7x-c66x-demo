`README.md` — what the demo does and how to build it.

`PINMUX.md` — header pins and which core owns them.

`MEMORY.md` — every shared memory region: its address, who writes it, and how each core caches it.

`docs/` — what spans several kinds of core: the fabric (`fabric.md`), the pipeline (`pipeline.md`), and the Debian and Yocto images' two kernels (`kernels.md`). What belongs to one kind of core is in that core's directory: `zephyr/r5/README.md`, `pru/README.md`, `dsp/README.md`, `linux-app/README.md`.

`tests/` — board tests, run from the PC over SSH: `run.sh` copies `board/` to the board and runs `check`, `soak`, or `routes` there. `tests/README.md` lists what each checks.

`LICENSE` — MIT, plus the files that keep their own license.

`linux-app/` — the `ai64` userspace program, a file per subcommand (`linux-app/README.md` lists them): `ai64.c` dispatches, `cores.c` is the table of every demo core that `ai64`, `ai64-demo`, and the web page read, and `util.c` holds what the subcommands share. `web/index.html` is the live page `ai64 web` serves, built in by `web_page.S`. `linux-app/ai64` is a build product.

`beagle-linux/` — the Debian overlay, the two patched kernel modules, the build script, and the on-board scripts.

`beagle-linux/overlays/` — the Linux device-tree overlay: the ICSSG pins, ICSSG0 RTU0's vring interrupt, and the DDR the fabric uses. The `.dtbo` blob is a build product.

`beagle-linux/kernel/pru_rproc/` — `pru_rproc` with the virtio kick, for ICSSG0 RTU0's RPMsg.

`beagle-linux/kernel/k3_r5_rproc/` — `ti_k3_r5_remoteproc` that can start an R5F again after a stop.

`beagle-linux/scripts/` — `build.sh` compiles in the containers; `ai64-demo` starts the demo on the board; `install-beagle.sh` sets up the Debian image once, so a reboot needs no manual steps.

`zephyr/` — the R5F apps, the three headers every core includes (`include/ai64_shm.h`, the bulk buffer and the PWM generators' status record; `include/ai64_fabric.h`, the fabric's layout and protocol; and `include/ai64_pipe.h`, the pipeline's, from P8.31 to P9.25), the eRPC interface (`erpc/ai64.erpc`) and its generated code (`erpc/shim/`, regenerated by `erpc/regen.sh`), the west manifest, and `patches/`, fixes to Zephyr that `scripts/apply-patches.sh` applies after each `west update`.

`zephyr/r5/` — Zephyr on the four main-domain R5F cores: an app for each, built together by one sysbuild build. `README.md` has what runs where.
- `r5f0_0/`, `r5f0_1/`, `r5f1_0/`, `r5f1_1/` — one core's app: `CMakeLists.txt`, `prj.conf`, `app.overlay` (its TI-SCI host and threads, its mailbox interrupt routes, its job's devices and pins), and `src/main.c`, which says what the core adds to the common code and starts its job, next to the job's own files. R5F0_0: SPI7 (`spi.c`), the bulk buffer (`bulk.c`), the UDMA channel (`dma.c`), and the pipeline's move (`pipe_dma.c`). R5F0_1: P9.25 (`pwm.c`) and the pipeline's last stage (`pipe_pwm.c`). R5F1_0: P8.18 (`blink.c`). R5F1_1: the monitor (`monitor.c`). `r5f0_0/sysbuild.cmake` adds the other three apps to its build.
- `common/` — what every core runs: `common.cmake` and `common.conf`, which each app includes; `ai64_ipc.dtsi`, the R5F-to-R5F `ipc_service` links; `dts/bindings/`, the two bindings; and `src/`: the RPMsg and eRPC link to Linux (`rpmsg.c`, `erpc.cpp`), the functions Linux calls (`linux_calls.c`), the links to the other cores (`ipc.c`), the fabric node (`fabric.c`), the mailbox route requests and the polled secure-proxy driver for TI-SCI (`tisci.c`, `sproxy.c`), the MPU setup (`mpu.c`), the restart cleanup (`restart.c`), and `ai64_r5.h`, the hooks a core fills in.

`zephyr/west.yml` — pins Zephyr at `zephyr/upstream`. From the repo root, `west init -l zephyr`.

`zephyr/upstream/` — generated upstream Zephyr checkout.

`.west/`, `modules/`, `bootloader/`, `tools/`, `build/` — generated west workspace. `build/zephyr/<core>/zephyr/ai64_<core>.elf` is each R5F core's image, `build/zephyr/r5f0_0/zephyr/ai64_r5f0_0.elf` and so on.

`pru/` — the ICSSG firmware, as two projects laid out the way TI's open-pru projects are: one directory per core, `<project>/firmware/beaglebone-ai64/icss_g<N>_<core>_fw/`, with its own `ti-pru-cgt/makefile` and `linker.cmd`. `pru/Makefile` builds both projects, and `pru_rules.mak` holds the rules every core's makefile includes.

`pru/pwm/` — ICSSG0: PWM in software on slice 0, with the ICSSG PWM module on slice 1, and with eCAP0, which slice 0's Tx_PRU runs; slice 1's PRU1 and RTU1 are also the pipeline's first stage, sampling P8.31. `firmware/` holds the project's memory map (`pwm_map.h`) and IPC records (`pwm_ipc.h`), and the RTU and Tx_PRU sources both slices build; each PRU's `main.c` is in its core's directory. `README.md` explains the project.

`pru/multicore_scheduler/` — ICSSG1: the port of open-pru's `examples/multicore_scheduler`, a `main.c` and a `pwm_toggle.asm` per core. BSD-3-Clause, as TI's original. `README.md` says what changed for J721E.

`pru/common/` — what both projects share: the trace-buffer log, the two resource tables (trace only, and RPMsg with trace), RTU0's RPMsg channel, text helpers, and the ICSSG register map (`icssg.h`).

`pru/build/` — generated ICSSG images, `ai64-icssg<ICSSG>-<pru|rtu|txpru><slice>.elf`, and their maps.

`dsp/c66x/`, `dsp/c7x/` — the C66x and C7x images, laid out like the R5F apps: `main.c` says what the core runs and starts each part, next to a file per part: `jobs.c`, Linux's job block; `fabric.c`, the core's fabric node (on the C66x, with the MPAX window it reads the GTC through); and `pipe.c`, its pipeline stage, the FFT on both C66x cores and the classifier on the C7x. The C7x also has `mmu.c`, its MMU and caches (with the control register accessors in `regs.asm`), and `mma.c`, the int8 layer on its Matrix Multiply Accelerator. `dsp/README.md` has the details. `dsp/include/` has what both share: the resource table and trace log, the shutdown handler, and the job block, which `linux-app/` includes too.

`dsp/build/` — generated DSP images, `ai64-c66x.elf` and `ai64-c7x.elf`.

`yocto/` — kas config and the `meta-ai64` layer. Recipes there build `ai64`, the R5F images, the twelve ICSSG images, and the DSP images; `recipes-kernel/` patches TI's 6.18 kernel so the R5F and C66x cores restart.

`media/` — the README's pictures: the bench photo, and logic analyzer captures of the demo's pins.

`containers/` — Containerfiles for the Linux, PRU, Zephyr, and DSP build images.

`third_party/` — generated checkouts used by the build (the PRU Software Support Package, EmbeddedRPC, and BeagleBoard-DeviceTrees). Not vendored.

`out/ai64-beagle/` — `build.sh bundle` output, copied to a Debian board and installed with its `install-beagle.sh`.
