`README.md` — what the demo does and how to build it.

`PINMUX.md` — header pins and which core owns them.

`LICENSE` — MIT, plus the files that keep their own license.

`linux-app/` — the `ai64` userspace program. `linux-app/ai64` is a build product.

`beagle-linux/` — the Debian overlay, the two patched kernel modules, the build script, and the on-board scripts.

`beagle-linux/overlays/` — the Linux device-tree overlay. The `.dtbo` blob is a build product.

`beagle-linux/kernel/pru_rproc/` — `pru_rproc` with the virtio kick, for RTU0's RPMsg.

`beagle-linux/kernel/k3_r5_rproc/` — `ti_k3_r5_remoteproc` that can start an R5F again after a stop.

`beagle-linux/scripts/` — `build.sh` compiles in the containers; `ai64-demo` starts the demo on the board; `install-beagle.sh` sets up the Debian image once, so a reboot needs no manual steps.

`zephyr/` — the R5F app, the shared-memory header every core includes (`include/ai64_shm.h`), the eRPC interface (`erpc/ai64.erpc`) and its generated code (`erpc/shim/`, regenerated by `erpc/regen.sh`), and the west manifest.

`zephyr/r5/` — Zephyr app for the four main-domain R5F cores. `boards/` holds each core's `.conf` and overlay (mailbox interrupt route); `src/` holds the RPMsg and eRPC code, the restart cleanup, the TI-SCI route request, and the MPU setup.

`zephyr/west.yml` — pins Zephyr at `zephyr/upstream`. From the repo root, `west init -l zephyr`.

`zephyr/upstream/` — generated upstream Zephyr checkout.

`.west/`, `modules/`, `bootloader/`, `tools/`, `build/` — generated west workspace. `build/zephyr-main_r5f0_0/zephyr/ai64_r5f0_0.elf` is the R5F0_0 image, and the other three cores build next to it.

`pru/icssg0/rtu0/` — RTU0, the transfer core (RPMsg and the DDR mailbox).

`pru/icssg0/pru0/` — PRU0, the SLIP frame on P8.11.

`pru/icssg0/txpru0/` — Tx_PRU0, the pulse trains on P9.25.

`pru/ring/` — the ring that the other nine ICSSG cores run (ICSSG0 slice 1, ICSSG1 slices 0 and 1): one `main.c`, built once per core, and a linker script for each kind of core. Each ring's PRU drives a square wave on one header pin.

`pru/include/` — the trace-buffer log and resource table the ICSSG cores share.

`pru/build/` — generated ICSSG images: `ai64-icssg0-pru0.elf`, `ai64-icssg0-rtu0.elf`, and `ai64-icssg0-txpru0.elf` for the demo, and `ai64-icssg<ICSSG>-<pru|rtu|txpru><slice>.elf` for the rings.

`dsp/c66x/`, `dsp/c7x/` — the C66x and C7x images and their linker scripts. `dsp/c7x/` also turns on the C7x MMU and caches (`ai64_c7x_mmu.c`, with the control register accessors in `c7x_regs.asm`). `dsp/include/` has what both share: the resource table and trace log, the shutdown handler, and the job block, which `linux-app/` includes too.

`dsp/build/` — generated DSP images, `ai64-c66x.elf` and `ai64-c7x.elf`.

`yocto/` — kas config and the `meta-ai64` layer. Recipes there build `ai64`, the R5F images, the twelve ICSSG images, and the DSP images; `recipes-kernel/` patches TI's 6.18 kernel so the R5F and C66x cores restart.

`containers/` — Containerfiles for the Linux, PRU, Zephyr, and DSP build images.

`third_party/` — generated checkouts used by the build (the PRU Software Support Package, EmbeddedRPC, and BeagleBoard-DeviceTrees). Not vendored.

`out/ai64-beagle/` — `build.sh bundle` output, copied to a Debian board and installed with its `install-beagle.sh`.
