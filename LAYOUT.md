`README.md` — what the demo does and how to build it.

`PINMUX.md` — header pins and which core owns them.

`LICENSE` — MIT, plus the files that keep their own license.

`linux-app/` — the `ai64` userspace program: `ai64.c`, and `ai64_fabric.c` for `ai64 fabric`, Linux's node on the fabric. `linux-app/ai64` is a build product.

`beagle-linux/` — the Debian overlay, the two patched kernel modules, the build script, and the on-board scripts.

`beagle-linux/overlays/` — the Linux device-tree overlay: the ICSSG pins, ICSSG0 RTU0's vring interrupt, and the DDR the fabric uses. The `.dtbo` blob is a build product.

`beagle-linux/kernel/pru_rproc/` — `pru_rproc` with the virtio kick, for ICSSG0 RTU0's RPMsg.

`beagle-linux/kernel/k3_r5_rproc/` — `ti_k3_r5_remoteproc` that can start an R5F again after a stop.

`beagle-linux/scripts/` — `build.sh` compiles in the containers; `ai64-demo` starts the demo on the board; `install-beagle.sh` sets up the Debian image once, so a reboot needs no manual steps.

`zephyr/` — the R5F app, the two headers every core includes (`include/ai64_shm.h`, the bulk buffer and the PWM generators' status record, and `include/ai64_fabric.h`, the fabric's layout and protocol), the eRPC interface (`erpc/ai64.erpc`) and its generated code (`erpc/shim/`, regenerated by `erpc/regen.sh`), the west manifest, and `patches/`, fixes to Zephyr that `scripts/apply-patches.sh` applies after each `west update`.

`zephyr/r5/` — Zephyr app for the four main-domain R5F cores. `boards/` holds each core's `.conf` and overlay (its TI-SCI host and threads, its mailbox interrupt route, and on R5F0_0 SPI7 and EHRPWM4); `dts/bindings/` the app's two bindings; `src/` the RPMsg and eRPC code, the fabric thread, the restart cleanup, the polled secure-proxy mailbox driver for TI-SCI (`ai64_sproxy.c`), the mailbox route request, the P9.25 PWM (`ai64_pwm.c`), and the MPU setup.

`zephyr/west.yml` — pins Zephyr at `zephyr/upstream`. From the repo root, `west init -l zephyr`.

`zephyr/upstream/` — generated upstream Zephyr checkout.

`.west/`, `modules/`, `bootloader/`, `tools/`, `build/` — generated west workspace. `build/zephyr-main_r5f0_0/zephyr/ai64_r5f0_0.elf` is the R5F0_0 image, and the other three cores build next to it.

`pru/` — the ICSSG firmware, as two projects laid out the way TI's open-pru projects are: one directory per core, `<project>/firmware/beaglebone-ai64/icss_g<N>_<core>_fw/`, with its own `ti-pru-cgt/makefile` and `linker.cmd`. `pru/Makefile` builds both projects, and `pru_rules.mak` holds the rules every core's makefile includes.

`pru/pwm/` — ICSSG0: PWM in software on slice 0 and with the ICSSG PWM module on slice 1. `firmware/` holds the project's memory map (`pwm_map.h`) and IPC records (`pwm_ipc.h`), and the RTU and Tx_PRU sources both slices build; each PRU's `main.c` is in its core's directory. `README.md` explains the project.

`pru/multicore_scheduler/` — ICSSG1: the port of open-pru's `examples/multicore_scheduler`, a `main.c` and a `pwm_toggle.asm` per core. BSD-3-Clause, as TI's original. `README.md` says what changed for J721E.

`pru/common/` — what both projects share: the trace-buffer log, the two resource tables (trace only, and RPMsg with trace), RTU0's RPMsg channel, text helpers, and the ICSSG register map (`icssg.h`).

`pru/build/` — generated ICSSG images, `ai64-icssg<ICSSG>-<pru|rtu|txpru><slice>.elf`, and their maps.

`dsp/c66x/`, `dsp/c7x/` — the C66x and C7x images and their linker scripts. Both are fabric nodes; the C66x maps the GTC through an MPAX window. `dsp/c7x/` also turns on the C7x MMU and caches (`ai64_c7x_mmu.c`, with the control register accessors in `c7x_regs.asm`). `dsp/include/` has what both share: the resource table and trace log, the shutdown handler, and the job block, which `linux-app/` includes too.

`dsp/build/` — generated DSP images, `ai64-c66x.elf` and `ai64-c7x.elf`.

`yocto/` — kas config and the `meta-ai64` layer. Recipes there build `ai64`, the R5F images, the twelve ICSSG images, and the DSP images; `recipes-kernel/` patches TI's 6.18 kernel so the R5F and C66x cores restart.

`containers/` — Containerfiles for the Linux, PRU, Zephyr, and DSP build images.

`third_party/` — generated checkouts used by the build (the PRU Software Support Package, EmbeddedRPC, and BeagleBoard-DeviceTrees). Not vendored.

`out/ai64-beagle/` — `build.sh bundle` output, copied to a Debian board and installed with its `install-beagle.sh`.
